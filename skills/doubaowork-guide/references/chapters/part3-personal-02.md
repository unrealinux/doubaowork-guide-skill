# 一场会议，从会前准备到待办落地

会开完了，事情却不一定跟着落地。讨论了不少内容，群里留下几句“回头跟进”，散会后再问谁负责、什么时候完成，大家往往还得重新翻记录。

哪些话已经形成决定，哪些还只是想法，哪些任务需要马上交给具体的人？先把这些分清楚，会议纪要才不会停在“记过了”，后面的跟进也才有依据。

一场会议可以按时间拆成三段，会前让参与者带着同一份背景进入讨论，会中保留原始记录，会后把决定和行动项交给具体的人。纪要只是中间的一步，还要继续连接上周任务和下次检查。

在整个流程里，模型适合处理整理、对照和提取。负责人、截止时间、延期原因和最终决策仍以原始材料为准。材料里没有写清楚的地方，保留待确认会比补一个完整答案更安全。

### 逐字稿整理成标准会议纪要

逐字稿里常见口头语、重复讨论和临时岔话，直接压缩很容易把结论一起压掉。整理时可以先识别议题，再分别提取讨论依据、明确决定、行动项和仍有分歧的事项。

```Plain Text
请阅读附件《产品周会逐字稿.docx》，将其整理成一份正式会议纪要。
请删除口头语、重复表达和与会议无关的内容，但不要改变发言人的原意。
纪要需要包含会议主题、时间、参会人、会议背景、议题讨论、明确结论、已确认决策、行动项和待确认事项。
只有原文明确提到的负责人和截止时间才能填写。原文没有说明的内容请标记为“待确认”，不要自行推测。
```

### 跟踪上次会议任务

单篇纪要解决的是本次发生了什么，两周材料放在一起才能回答事情有没有继续推进。核对时应当逐项沿用上周的行动项名称，再从本周逐字稿里寻找完成证据、延期说明或取消决定。没有被提到的任务不能自动算作完成。

```Plain Text
请同时阅读《上周会议纪要.docx》和《本周会议逐字稿.docx》。
逐项核对上周会议中的行动项，并根据本周会议内容判断其状态，包括已完成、进行中、延期、取消和未提及。
对于延期任务，请提取延期原因、新的截止时间和责任人；对于本周新增任务，请单独列出。
最后生成“上周任务跟踪表”和“本周新增行动项”两个部分。
```
