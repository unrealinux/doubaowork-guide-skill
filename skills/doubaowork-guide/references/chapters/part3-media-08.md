# 爆款公众号文章转短视频

很多人把公众号文章改成短视频，做法特别简单粗暴：复制全文，扔给 AI，说一句“帮我改成 60 秒口播”。

然后 AI 也很配合。它删掉一半内容，再加一句“你敢相信吗”，最后补一个“赶紧点赞收藏”。字是少了，视频却不一定能用。更麻烦的是，原文里的条件、时间和个人实测，很容易在这一删一改里变味，变得夸张。。。

这次我拿自己的公众号文章《我把电脑外包给豆包后，效率飞升！【附教程】》做了一次完整实测：先把原文扒下来；再让豆包工作的短视频脚本编剧Skill出脚本和分镜；然后准备真人口播、操作录屏、图片组成的素材包；最后使用Remotion Skill剪辑，最后导出本地成片。

整条链路是这样的：

```text
公众号原文
→ 短视频脚本与逐秒分镜
→ 真人口播 + 产品录屏 + 配图素材包
→ Remotion Skill
→ 代码检查、渲染、ffprobe 和抽帧验收
→ 本地 MP4 成片
```

PS：本次只做到本地成片，没有替作者上传，也没有发布到抖音、视频号或 B 站。

## 先选工具：编剧和剪辑是两件事

| 阶段 | 本次采用 | 负责什么 |
|-|-|-|
| 原文整理 | 网页正文提取  | 留住原文事实、条件和案例顺序 |
| 脚本与分镜 | 短视频脚本编剧（工作伙伴） | 选角度、写口播、拆逐秒画面、做事实自检 |
| 素材管理 | 豆包工作本地电脑能力 + 素材清单 | 核对视频、录屏、图片和本地路径是否存在 |
| 真正剪辑 | Remotion Skill | 复用项目、组织时间线、渲染 H.264 MP4（剪辑） |
| 验收 | ffprobe + 均匀抽帧 | 检查时长、分辨率、帧率、音轨、黑屏和截断 |

为什么不用一个提示词把所有事都包掉？因为脚本的问题和剪辑的问题完全不是一回事。脚本不好，你要改的是信息取舍；素材缺失，你要补拍；成片黑屏或音轨不对，是剪辑工程。这两个流程拆开，哪一步出问题才好一眼看出来。

### 可直接复制的脚本提示词

```text
我是一名公众号作者，准备把自己的长文《我把电脑外包给豆包后，效率飞升！【附教程】》改成一条 3 分钟以内、可以直接拍摄和剪辑的短视频。

输入材料：
- 原文链接：https://mp.weixin.qq.com/s/teHaz6ple6hd4vawV6vl-Q
- 已从原文清洗并核验的事实母稿：上传的《公众号原文事实母稿.md》

请你以“短视频脚本编剧”的工作方式处理：
1. 先读取事实母稿，列出不能改坏的事实和需要保留限定词的数字。
2. 从四个真实任务里挑最适合短视频表达的 3 个，不要为了塞满而把所有内容念一遍。
3. 写一版 150—180 秒的第一人口播稿。开头 5 秒直接制造反差：豆包不是陪聊，而是在电脑里替我干活。
4. 口语化、短句、有停顿感，保留“袋鼠帝”本人实测的语气；不要写成产品发布会，也不要加入没发生过的功能。
5. 把口播稿拆成逐镜头表格，包含：时间段、口播、画面、素材类型、屏幕大字、转场、风险备注。
6. 优先复用现有口播视频、产品操作录屏和文章配图；缺素材的镜头明确标“需补拍”，不要假装素材已经存在。
7. 最后做一次事实自检，逐项检查平台差异、帧率、时长、数量、发布日期和“效率提升”是否仍保留原文条件。

最终请交付：
- 口播稿
- 逐镜头剪辑表

聊天里只汇总：成片建议时长、镜头数、复用素材数、需补拍数。

安全边界：只生成本地脚本和分镜，不上传、不发布，不修改原素材，也不要把个人实测写成普遍承诺。
```

## 第三步：整理素材包

短视频脚本解决了拍什么的问题，素材包是决定画面的重要因素。

| 素材 | 作用 |
|-|-|
| 前段真人口播 | 开场、问题和能力解释 |
| 中段操作录屏与口播 | 三个真实任务的电脑操作过程 |
| 结尾真人口播 | 结论和行动提示 |
| 视频封面 | 片头或平台封面 |
| 豆包工作任务模式截图 | 解释“不是只聊天” |
| 技能与连接器截图 | 解释为什么有现成工具要优先用 |

我还给每个素材编辑了合适的名称。这样豆包工作在剪辑的时候方便知道，什么情况用哪个对应的素材。

### 可直接复制的 Remotion 剪辑提示词

```text
请使用当前已安装的 Remotion Skill，把“豆包电脑外包”素材包剪成一条可播放的视频。

输入：
- 口播视频、操作录屏和配图：以《素材清单.md》中列出的本地路径为准
- 口播稿与逐镜头剪辑表：使用上一阶段已验收的文件
- 已有 Remotion 项目：替换成你自己的本地项目绝对路径

执行要求：
1. 先检查素材清单和文件是否存在，缺失项先列出来，不要编造。
2. 复用已有 composition `DoubaoDesktopBilibili`，不要重建项目，不要覆盖原始视频。
3. 保留真人口播主线，在对应段落插入产品操作录屏、界面图和章节提示；避免用装饰动画盖住真实界面。
4. 画面比例、分辨率、时长以现有 composition 为准；所有数字和功能描述必须符合事实母稿。
5. 运行代码检查和类型检查，再渲染 H.264 MP4。
6. 渲染后用 ffprobe 核对时长、分辨率、帧率、视频编码和音轨；再均匀抽帧检查开头、三个案例段、结尾有没有黑屏、错字、截断和隐私信息。

最终交付：
- 本地 MP4 成片
- 一张接触表或多张验收抽帧
- 一份简短验收记录，写清文件路径、媒体参数和已知限制

安全边界：只在本地项目中生成新文件，不删除或覆盖原素材，不上传、不发布。
```
