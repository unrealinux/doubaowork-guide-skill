# 今天写什么：从热点、同行到本周选题

做内容最难受的时刻，恰恰不是没有选题，我经常出现这种情况：桌面上躺着二三十个题目，却不知道今天到底先写哪个。

热点看了一圈，怕是旧闻；同行爆文拆了一堆，又怕写成低配版复刻；好不容易攒出一长串选题，却发现产能又跟不上了。

这一篇，我们不让豆包工作直接替你“拍脑袋选题”。直接把真实流程分成以下三步：

1. 先做一份带来源、带时间的热点早报；
2. 再挑一篇同行的内容，拆解方法，不照抄内容；
3. 最后结合账号定位和我们实际的产能，把候选题排成一周能执行的行动日历。

这三步跑完，得到的不只是一串选题，是一条能重复使用的内容生产线。

## 这次用到的最优skill组合

| 任务 | 最终采用的组合 | 为什么这样选 |
|-|-|-|
| 当日热点早报 | VOC 与舆情调研 + 豆包工作公开网页检索 | 能筛选内容、溯源原帖，也能把旧闻和新报道分开 |
| 同行内容拆解 | 公众号图文与运营策略 + 链接读取 + Lark Doc | 一次完成读原文、事实验真、结构拆解和飞书交付 |
| 本周选题排期 | 爆款标题与选题日历 + Lark Doc | 不只给标题，还会按读者收益、可验证性和执行成本排产能 |

我原本还找到一个叫「博查 AI 搜索」连接器。它用来搜索其实很合适，但安装时需要单独填写 API Key（有点麻烦，就不推荐给大家了）。对于第一次照着教程做的朋友，如果能开箱即用，是最方便的。已经有博查 API Key 的朋友，可以把它作为任务一的增强搜索源。

这里有一个很容易忽略的细节：这个 Skill 明确写着只适合网页端和电脑端。我们在豆包工作桌面端，可以直接跑；但如果你在手机上做，这个Skill 就不会被触发了。

### 第二步：提示词别只写“今天有什么 AI 新闻”

如果你只问一句“今天有什么热点”，AI 很容易把今天新发的旧闻也塞进来。更好的写法是，要同时交代时间窗、信源顺序、筛选标准和待核验规则。

这次我实际使用的提示词核心是：

#### 可直接复制的实测提示词

```text
我是一名科技 / AI 类公众号编辑，今天需要为编辑部准备一份「AI 行业选题早报」。

请使用当前已附加的「VOC与舆情调研」技能及豆包工作可用的公开网页检索能力，检索并核验中国标准时间 2026 年 8 月 26 日 00:00 至 2026 年 8 月 27 日当前时间公开发布的 AI 行业信息，重点关注：
- 大模型与 Agent 产品更新；
- AI 办公、内容创作和开发者工具；
- 会真正影响普通职场人的新功能或变化。

请按下面的步骤处理：
1. 先说明本次检索的截止时间和覆盖范围。
2. 区分「事件发生时间」和「文章发布时间」，旧闻不得写成今日新闻。
3. 合并同一事件的重复报道，优先使用官方公告、官方博客或产品更新页。
4. 筛选 5 条最值得编辑部关注的信息，每条给出：事件、为什么值得关注、可以怎么写、原始来源链接、时间依据、待确认点。
5. 最后只推荐 3 个最值得今天动手的选题，按「账号匹配度、时效性、读者收益、可验证性」说明推荐理由。
6. 对不能确认的数字、价格、版本号和产品能力单独标注，不要补写或猜测。

最终请交付一份结构清晰的中文 Markdown 早报，包含「今日信息表」「今日优先选题」和「待人工复核」三部分。

未经我确认，不要发布内容，不要发送消息，不要修改线上文档或数据。
```

### 第三步：先校验时间，再查热点

最容易翻车的情况：把其他媒体今天重新发了一篇已经过时的东西误写成“产品今天刚发布”。解决方法：只要在提示词里把两个时间拆开，就能过滤掉那些已经过时了的新闻。

### 帮你筛选最优的新闻

这次豆包工作最终交付了一份约 20KB 的 Markdown 早报：

- 先筛出 5 条重点信息；
- 再收敛成 3 个优先选题；
- 额外列出 10 项写作前必须复核的信息；
- 还抓出 4 条“文章近期出现，但事件本身不在时间窗内”的旧闻。

在这份实测里，它推荐的三个方向分别是“国产开源大模型同日双发对比”“百度搭子行业套件实测”和“Qoder 非程序员视角体验”。

这是我前两天跑的，那时候刚好是几个flash模型开源的时间，第一个选题绝对能爆。

这里注意不要机械照抄结论，因为热点每天都在变，筛选方法却是一直复用的。

## 任务二：同行爆了什么，可以拆解，但不能照抄

热点早报里出现了一篇 36 氪公开文章，标题讲的是 GLM-5.3-Flash、“牛来”模型、国产算力和价格对比。我没有让豆包工作“仿写一篇”，而是把它当作一个同行样本来拆。

### 第一步：选对拆解工具

这一步使用「公众号图文与运营策略」。它不只会润色文章，还包含选题、验真、文章评估和运营复盘，并且正式成果会先交付为飞书在线文档。

![图01-05｜找到同行拆解能力](https://doubaowork.homes/media/H3ftwrpv-05-9714fd014765.png)

### 第二步：把“学什么”和“不能抄什么”写进提示词

#### 可直接复制的实测提示词

```text
我是一名科技 / AI 类公众号编辑。请使用「公众号图文与运营策略」技能，拆解下面这篇公开文章，但不要照抄文章表达：

文章链接：https://36kr.com/p/3956946155355267

请按下面的顺序处理：
1. 先读取文章，并列出你实际读取到的标题、作者 / 媒体、发布时间和原始链接；读不到的字段标为「待确认」，不要猜。
2. 把文章中的「可核验事实」和「作者的判断 / 修辞」分开。涉及参数、价格、跑分、用户量和性能对比时，说明原文依据是否足够。
3. 从 6 个维度拆解它为什么容易吸引点击和读完：开头钩子、标题承诺、叙事结构、信息密度、证据用法、结尾动作。
4. 输出一张拆解表，每个结论都要带文章中的位置依据或内容摘要；不要连续摘抄原文，不要复制有辨识度的句式。
5. 总结 5 个可以学的方法、3 个不能照搬的元素、5 个写作前必须复核的事实。
6. 基于同一事件，给我的公众号设计 3 个全新的选题角度，面向普通职场人和开发者，强调实测、教程或决策价值，不做同义改写。
7. 做一次自检：是否把作者观点写成事实，是否混淆文章发布时间和事件发生时间，是否出现无法追溯的数字。

请将最终结果写入一份新的飞书文档，标题为「同行内容拆解｜GLM-5.3-Flash｜2026-08-27 实测」，并返回可访问链接。

未经我确认，不要发布内容，不要发送消息，不要修改其他线上文档或数据。
```

这里最关键的是三句边界：事实和观点分开、每条结论给位置依据、不能连续摘抄。没有这三句，拆解很容易变成高级一点的洗稿。

豆包工作先读取 36 氪页面，然后加载公众号写作和 Lark Doc 能力，生成文档草稿，校验通过后再创建飞书文档。

### 把爆文拆成能学习复用的方法

最终结果并没有停在空话上，相反的，给出了：

- 13 项可核验事实，并逐条判断依据是否充分；
- 8 处作者判断或修辞，避免把观点写成事实；
- 6 个传播维度的拆解；
- 5 个可学方法、3 个不能照搬的元素、5 个写作前必须复核的事实；
- 3 个基于同一事件、但需要原创实测数据支撑的新选题。

比如，文章里“价格只有 1/40”很有冲击力，但输入和输出如何加权并不明确；“57 分持平”只来自单一榜单；“10 万张国产芯片”没有披露型号。豆包工作没有把这些数字直接当成铁证，而是先留在了复核清单里。

## 最后，记住这套提示词骨架

以后换成法务、HR、销售、产品经理，也可以直接套这四层：

1. **先写清角色和受众**：你是谁，内容给谁看；
2. **再写清约束**：时间窗、产能、数据权限、不能做什么；
3. **规定判断标准**：匹配度、收益、时效、证据、成本；
4. **要求留下复核清单**：哪些是事实，哪些是假设，哪些数字还不能写。

AI 真正好用的地方，在于帮你把 30 个筛选到 3 个，这样的选题越精越好，并且告诉你：为什么是这 3 个，今天先做哪个，写之前还要复核哪些内容。

这才是内容团队真正能落地的“今天写什么”。
